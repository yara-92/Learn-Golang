并不是所有网站都适合做成静态站点，但下面这些场景中，Hugo 通常是很好的选择：

## 适合的场景

- **技术博客 / 个人博客**：内容更新频率不高，读多写少
- **产品文档站**：结构化的 Markdown 文档，需要快速构建和部署
- **企业官网 / 落地页**：内容相对固定，追求首屏加载速度
- **开源项目主页**：直接托管在 GitHub Pages 上，零成本

## 不太适合的场景

- 需要用户登录、评论、实时互动等强动态功能的应用（不过可以通过第三方服务如 Disqus、Giscus 弥补评论功能）
- 内容由非技术人员通过可视化界面频繁编辑的场景（除非搭配无头 CMS）

## 部署到哪里

生成的 `public/` 目录是一堆纯静态文件，几乎可以部署到任何地方：

- GitHub Pages / GitLab Pages
- Cloudflare Pages
- Netlify / Vercel
- 任意支持静态文件的对象存储 + CDN（如阿里云 OSS、腾讯云 COS）
- 自己的 Nginx 服务器
